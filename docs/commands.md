# cmo command reference

Generated by `make docs` from `cmo <command> --help`.

## cmo

```text
cmo (Cert Manager Operator CLI) installs and removes cert-manager, and creates,
lists, inspects, renews and deletes its issuers and certificates.

On OpenShift it installs the Red Hat cert-manager Operator through OLM. On any
other Kubernetes cluster it applies the upstream cert-manager release manifest.
It picks the right one by itself.

Get started:
  cmo install                                   install cert-manager
  cmo issuer create ca my-ca --generate         make a CA to sign with
  cmo cert create web --issuer my-ca --dns web.example.com
  cmo cert inspect web                          see what was issued
  cmo status                                    check on everything

Usage:
  cmo [command]

Available Commands:
  cert        Create, list, inspect, renew and delete certificates
  completion  Generate shell completion scripts
  doctor      Check the cluster, the cert-manager install, and every issuer and certificate
  help        Help about any command
  install     Install cert-manager (OLM on OpenShift, the release manifest elsewhere)
  issuer      Create, list, show and delete issuers and cluster issuers
  status      Show whether cert-manager is installed and healthy
  uninstall   Remove cert-manager from the cluster
  version     Print the cmo version

Flags:
      --context string      kubeconfig context to use
  -h, --help                help for cmo
      --kubeconfig string   path to the kubeconfig (default: $KUBECONFIG, then ~/.kube/config)
  -n, --namespace string    namespace (certificates: default is the context's namespace; issuers: set it for a namespaced Issuer, leave it out for a ClusterIssuer)
      --no-color            don't color the output (also: NO_COLOR=1)
  -o, --output string       output format: table, wide, json or yaml (default "table")
      --timeout duration    how long to wait for things to become ready (default depends on the command)
  -v, --verbose             trace the cluster API requests on stderr
      --version             version for cmo
  -y, --yes                 don't ask for confirmation

Use "cmo [command] --help" for more information about a command.
```

## cmo install

```text
Install cert-manager and wait until it is ready to issue certificates.

On OpenShift, cmo subscribes to the Red Hat cert-manager Operator
(openshift-cert-manager-operator from redhat-operators) in the
cert-manager-operator namespace. With no --version it follows the package's
default channel; with --version it pins that release (Manual approval, only
its InstallPlan is approved).

On other Kubernetes clusters, cmo server-side applies the upstream
cert-manager.yaml for --version (default v1.21.3).

Running it again is safe: what is already in place is left alone.

Usage:
  cmo install [flags]

Examples:
  cmo install
  cmo install --version v1.18.0          # pin an operator release on OpenShift
  cmo install --platform kubernetes --version v1.20.2
  cmo install --manifest ./cert-manager.yaml   # air-gapped Kubernetes
  cmo install --dry-run                  # print what would be applied

Flags:
      --channel string            OLM channel (OpenShift; default: stable-vX.Y for --version, else the package default)
      --dry-run                   print the objects that would be applied, and change nothing
  -h, --help                      help for install
      --manifest string           manifest file or URL to apply instead of the release download (Kubernetes)
      --no-wait                   return once applied, without waiting for cert-manager to be ready
      --platform string           auto, openshift or kubernetes (default "auto")
      --source string             OLM CatalogSource (OpenShift) (default "redhat-operators")
      --source-namespace string   namespace of the CatalogSource (OpenShift) (default "openshift-marketplace")
      --version string            version to install, such as v1.18.0 (OpenShift: operator version; Kubernetes: cert-manager release)

Global Flags:
      --context string      kubeconfig context to use
      --kubeconfig string   path to the kubeconfig (default: $KUBECONFIG, then ~/.kube/config)
  -n, --namespace string    namespace (certificates: default is the context's namespace; issuers: set it for a namespaced Issuer, leave it out for a ClusterIssuer)
      --no-color            don't color the output (also: NO_COLOR=1)
  -o, --output string       output format: table, wide, json or yaml (default "table")
      --timeout duration    how long to wait for things to become ready (default depends on the command)
  -v, --verbose             trace the cluster API requests on stderr
  -y, --yes                 don't ask for confirmation
```

## cmo uninstall

```text
Remove cert-manager: the operator (OpenShift) or the release manifest objects
(Kubernetes), the cert-manager namespace and the webhook configurations.

The CRDs stay, and with them your Certificates, Issuers and the Secrets they
wrote, so a later cmo install picks up where you left off. --purge deletes the
CRDs too, and so every cert-manager object in the cluster.

Usage:
  cmo uninstall [flags]

Examples:
  cmo uninstall
  cmo uninstall --purge --yes    # everything, without asking

Flags:
  -h, --help              help for uninstall
      --manifest string   manifest file or URL to remove (Kubernetes)
      --no-wait           don't wait for the namespaces to finish deleting
      --purge             also delete the cert-manager CRDs, and with them every Certificate and Issuer
      --version string    release whose manifest to remove (Kubernetes; default: the installed one)

Global Flags:
      --context string      kubeconfig context to use
```

## cmo issuer create ca

```text
Create an issuer that signs with a CA key pair.

--secret uses a kubernetes.io/tls Secret you already have (for a ClusterIssuer
it must be in the cert-manager namespace).

--generate makes a new root CA: a self-signed bootstrap issuer NAME-selfsigned,
a 10-year ECDSA P-256 root CA Certificate NAME-root-ca, and the CA issuer NAME.
cmo issuer delete NAME removes all three.

Usage:
  cmo issuer create ca NAME [flags]

Examples:
  cmo issuer create ca my-ca --generate
  cmo issuer create ca my-ca --generate --common-name "Lab Root CA"
  cmo issuer create ca corp-ca --secret corp-ca-keypair

Flags:
      --common-name string   common name of the generated root (default NAME-root-ca)
      --dry-run              print the objects that would be created, and change nothing
      --duration duration    lifetime of the generated root (default 87600h, 10 years)
      --generate             generate a new self-signed root CA
  -h, --help                 help for ca
      --no-wait              don't wait for the issuer to be Ready
      --secret string        existing TLS Secret holding the CA key pair

Global Flags:
```

```text
      --email test@example.com --http01-ingress-class openshift-default
  cmo issuer create acme dns --server letsencrypt --email me@example.com \
      --dns01-rfc2136-nameserver 10.0.0.53:53 --dns01-rfc2136-tsig-key-name cmo \
      --dns01-rfc2136-tsig-secret tsig-key

Flags:
      --dns01-rfc2136-nameserver string        solve DNS-01 by RFC2136 update to this server (host:port)
      --dns01-rfc2136-tsig-algorithm string    TSIG algorithm (default "HMACSHA256")
```

## cmo cert create

```text
Request a certificate from an issuer and wait until it is issued.

--issuer names an Issuer in the certificate's namespace or, if there is none
by that name, a ClusterIssuer. --cluster-issuer skips the Issuer lookup.

Usage:
  cmo cert create NAME [flags]

Examples:
  cmo cert create web --issuer my-ca --dns web.example.com
  cmo cert create api --issuer my-ca --dns api.example.com,api.internal --ip 10.0.0.10 -n team-a
  cmo cert create mtls --issuer my-ca --common-name client-1 --key-algorithm ecdsa --key-size 384
  cmo cert create short --issuer my-ca --dns s.example.com --duration 2h --renew-before 1h
  cmo cert create web --issuer my-ca --dns web.example.com --dry-run

Flags:
      --ca                      issue a CA certificate
      --cluster-issuer          --issuer is a ClusterIssuer even if an Issuer has the same name
      --common-name string      subject common name
      --dns strings             DNS names (comma separated, or repeat the flag)
      --dry-run                 print the Certificate that would be created, and change nothing
      --duration duration       lifetime, such as 2160h (default: cert-manager's 90 days)
  -h, --help                    help for create
      --ip strings              IP address SANs
      --issuer string           issuer to sign with (an Issuer in the namespace, else a ClusterIssuer)
      --key-algorithm string    rsa, ecdsa or ed25519 (default: cert-manager's, RSA 2048)
      --key-size int            key size: rsa 2048/3072/4096, ecdsa 256/384/521
      --no-wait                 don't wait for the certificate to be issued
      --renew-before duration   renew this long before expiry (default: cert-manager's, a third of the lifetime)
      --secret string           Secret to write the key pair to (default NAME-tls)
      --uri strings             URI SANs, such as spiffe://cluster.local/ns/a/sa/b

Global Flags:
      --context string      kubeconfig context to use
      --kubeconfig string   path to the kubeconfig (default: $KUBECONFIG, then ~/.kube/config)
  -n, --namespace string    namespace (certificates: default is the context's namespace; issuers: set it for a namespaced Issuer, leave it out for a ClusterIssuer)
      --no-color            don't color the output (also: NO_COLOR=1)
  -o, --output string       output format: table, wide, json or yaml (default "table")
      --timeout duration    how long to wait for things to become ready (default depends on the command)
```

```text
      --no-color            don't color the output (also: NO_COLOR=1)
```
